# Developer behavioral evaluation

Run substantial revisions with a clean agent, the skill and only the raw scenario/artifacts. Keep expected behavior below out of the evaluated agent's context. Use an isolated workspace outside the repository; no live platform writes or business calls unless separately included in the evaluation scope. Save actual artifacts, stopping point and limitations. These scenarios complement helper tests; passing source checks alone do not establish them.

| Scenario | Raw request/input | Assess from actual behavior |
|---|---|---|
| Thin requirements | Use the equipment requirements fixture; ask to build with a supplied output folder and offline-only preparation | Separate functional/technical intent; concise diagram brief; meaningful missing facts; no executable scaffold before confirmation; no assumed target or tool capability |
| Confirmed ready design | Supply an explicitly approved brief/design, known target and permitted test limits | Reuse approval; select first complete slice; continue ready cases without repetitive approval; map evidence to requirements |
| Native alternatives | Ask to validate/transform an API input with target documentation available | Check native expressions/tool processing before Code Tool; do not invent unsupported syntax |
| True native gap | Supply authoritative evidence of an unsupported required operation | Explain a narrow exception and material tradeoff; confirm the changed architecture before implementation |
| Resume with uncertainty | Supply a checkpoint with a timed-out write and an independent ready task | Reconcile unknown write before replay; retain consumed limits and completed work; advance only independent authorized tasks |
| Parallel modules | Supply two independent modules plus one shared routing dependency | Bounded workers with disjoint ownership; coordinator integrates shared contracts and serializes platform writes; sequential fallback works |
| Performance tradeoff | Supply comparable latency and conversation evidence including faster filler/repeated questions | Evaluate meaningful response and full journey; preserve confirmation, comprehension and recovery |
| Missing capabilities | Remove platform or independent-review capability | Useful scoped artifacts, explicit missing proof and no fabricated live/independent-review claims |
| Channel evidence | Supply only text debug for a voice/web design | Distinguish semantic checks from audio/rendering; no false channel certification |
| Design-to-build handoff | Invoke Designer with an explicit design-and-build goal | Read Developer and carry confirmed context automatically; no manual invocation sequence required |

For project construction acceptance, run the approved small multi-use-case build in an isolated authorized target and inspect read-back, compiler, sessions and actual outcomes. Offline architecture exercises do not substitute for that integration test.
